1. **Фрезеровка фанеры на ЧПУ: что указать в заказе.** Материал и толщина, размеры деталей, отверстия, внутренние углы, подготовка чертежа. URL: `/blog/frezerovka-fanery-chpu-chto-ukazat-v-zakaze`.
2. **Фрезеровка МДФ на ЧПУ: что согласовать до изготовления.** Контур и углубления, глубина относительно толщины, лицевая сторона, разграничение фрезеровки и последующей отделки. URL: `/blog/frezerovka-mdf-chpu-chto-soglasovat`.
3. **Сколько стоит фрезеровка на ЧПУ: какие данные нужны для расчёта.** Факторы расчёта, смысл тарифа за погонный метр, сравнение состава предложений и шаблон обращения. Без неподтверждённых цен. URL: `/blog/skolko-stoit-frezerovka-chpu-kak-poluchit-raschet`.

У каждой статьи свои title, description и краткое описание. Статьи связаны между собой и ведут на `/services/cnc-milling` и к существующей заявке `#cnc-request`. Общие рекомендации отделены от подтверждённых условий мастерской. Фото работ не добавлены: реальных фотографий нет, подменять их вымышленными нельзя.

## Редакторская проверка

Все три текста проверены через API Google, модель `google/gemini-3.8-flash`. Редактор отметил практическую пользу, соответствие намерению заказчика и отсутствие критичных технических ошибок. Применены замечания: уточнены условия подготовки файла, убран двусмысленный намёк на отделку в описании МДФ, унифицирован адрес, в шаблоне запроса отдельно обозначен вопрос материала и исправлена неестественная фраза о странице услуги. Ошибочную ссылку на якорь заявки нашли и исправили отдельно по коду.

Это редакторская проверка, а не достоверное определение авторства текста или подтверждение всех фактов внешним экспертом. Длинных тире в публикациях нет. Общий текст не выдаёт себя за историю выполненных заказов.

## Техническая проверка

PostgreSQL-парсер принял весь SQL-файл: транзакцию и три вставки. Из сохранённых текстов сгенерированы три HTML-документа существующим генератором: полный текст, один description и правильный canonical в каждом. Шесть существующих тестов SEO и фактов ЧПУ прошли. Все три черновика открыты в браузере с подставленными ответами статей; на телефоне горизонтального переполнения нет, переход на существующую страницу услуги проверен. Это проверка черновиков, не выполнение импорта в рабочую базу и не подтверждение появления новых статей на сайте.

## Добавление на рабочий сайт

Подготовлен `server/scripts/import-blog-posts-cnc-2026-11.sql`. Импорт выполняется одной транзакцией, повторный запуск пропускает существующие адреса, не меняет старые тексты и даты. Дата публикации новых статей устанавливается при первом импорте в базу. Выполнение на production в этой работе не подтверждено.

На VPS, после получения последнего кода:

```bash
cd /opt/faktura/server
git pull
sudo docker exec -i supabase-db psql -U postgres -v ON_ERROR_STOP=1 < scripts/import-blog-posts-cnc-2026-11.sql
sudo docker exec supabase-db psql -U postgres -c "select slug, is_published, published_at from public.blog_posts where slug in ('frezerovka-fanery-chpu-chto-ukazat-v-zakaze', 'frezerovka-mdf-chpu-chto-soglasovat', 'skolko-stoit-frezerovka-chpu-kak-poluchit-raschet') order by slug;"
```

Затем повторить размещение в Timeweb. Существующая сборка берёт статьи из рабочего API и генерирует HTML и sitemap; импорт должен предшествовать сборке. Отдельный сервис и новая система публикаций не нужны.
